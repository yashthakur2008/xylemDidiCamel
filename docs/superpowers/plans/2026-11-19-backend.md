# LeakLens Backend Implementation Plan

> **For agentic workers:** Execute inline with the executing-plans workflow. Use test-first steps and review checkpoints.

**Goal:** Deliver a runnable, persistent demo API for LeakLens Water Quality risk and incident response.

**Architecture:** FastAPI routes validate inputs and enforce bearer-token roles. Small domain functions apply transitions to a versioned demo state stored transactionally in SQLite. Fictional data only; no outbound messaging or equipment integration.

**Tech Stack:** Python 3.11+, FastAPI, Pydantic, Uvicorn, standard-library SQLite, pytest and HTTPX.

**Spec:** `docs/LEAKLENS-DESIGN.md`, amended by the user's explicit request to implement a backend on November 19 Pacific.

## Global constraints
- Below 20 psi is a demo operational threshold, not proof of contamination.
- Two clear samples is a configurable demo policy requiring California regulatory review.
- Operator approves notices, assignments and clearance. Crew records work/samples only after assignment.
- No outbound notices, control commands, real customer data or claims of production utility readiness.
- Backend supersedes localStorage-only persistence for clients that integrate it. Frontend integration is separate.

## File responsibilities
- `backend/leaklens/api.py`: application factory, typed routes, CORS and role dependencies.
- `backend/leaklens/models.py`: strict request models, bounds and whitespace validation.
- `backend/leaklens/network.py`: fictional network and explainable weighted scores.
- `backend/leaklens/store.py`: SQLite versioned document, atomic transactions and schema validation.
- `backend/leaklens/events.py`: telemetry and incident state transitions with audit entries.
- `backend/tests/test_api.py`: real FastAPI interfaces with temp persistent database.
- `backend/scripts/smoke.py`: actual HTTP workflow against running Uvicorn.
- `backend/README.md`: configuration, endpoint contracts, smoke test and deployment limits.
